# Tutorial: Kokoro voices + Remotion + Three.js

This guide takes you from a script to generated narration and a rendered animated short in this repository. It covers two related but different animation routes:

1. **Remotion + Three.js / React Three Fiber** — the main 3D cartoon shorts, with a React composition that can be previewed and rendered frame-by-frame.
2. **Standalone Three.js Stage Kit** — the separate pop-up-book and low-poly projects under `ucimesehrou/`; these use the repository's `K` API and do **not** use Remotion.

Use one route for a project. Do not try to place a standalone `registerStyle()` file inside a Remotion composition. For storyboarding, polished transitions, fluid morphing, deterministic particles, and detailed motion craft, continue with [`ANIMATION_TUTORIALS.md`](ANIMATION_TUTORIALS.md). Unless the user explicitly requests otherwise, each finished video must be 60–70 seconds total (target 65 seconds; 1,950 frames at 30 fps).

## 1. Install the project tools

From the repository root, install the Node packages locked for this checkout:

```bash
npm ci
```

Confirm Node and npm are available:

```bash
node --version
npm --version
```

For voice generation, install Python 3 and `ffmpeg`. On macOS with Homebrew:

```bash
brew install ffmpeg
python3 --version
ffmpeg -version
```

On Ubuntu/Debian:

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg python3 python3-venv python3-pip
```

Create and activate the repo's ignored virtual environment (macOS/Linux):

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install kokoro-onnx soundfile faster-whisper
```

The checked-in generator uses `kokoro-onnx` rather than the `kokoro` package. Its comment explains that the latter can fail to install under Python 3.13. The script also invokes the `ffmpeg` executable and uses faster-whisper to create word timestamps.

Windows PowerShell activation is:

```powershell
py -3 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install kokoro-onnx soundfile faster-whisper
```

Install an ffmpeg build and ensure `ffmpeg.exe` is on `PATH` on Windows.

## 2. Generate narration with Kokoro

### 2.1 Write and save the narration

Save a plain UTF-8 text script. For example:

```bash
mkdir -p out/voice-demo
cat > out/voice-demo/script.txt <<'EOF'
A tiny change can transform an entire landscape. First, the seed opens. Then roots reach for water, and a new tree rises toward the light.
EOF
```

Use short sentences and punctuation for natural pauses. Read the script aloud before generating it; revise words that are hard to pronounce. For factual videos, keep a separate source list with the script.

### 2.2 Put the Kokoro ONNX model files in the output folder

`scripts/voice.py` expects these exact files **inside the output directory**:

- `kokoro-v1.0.onnx`
- `voices-v1.0.bin`

Download the files from the Kokoro ONNX model release referenced in the script header:

```bash
cd out/voice-demo
curl -fL 'https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.onnx' -o kokoro-v1.0.onnx
curl -fL 'https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin' -o voices-v1.0.bin
cd ../..
```

If the release changes its filenames or assets, use the exact matching ONNX model and voice bundle from the URL linked in `scripts/voice.py`; do not rename an unrelated file and assume it will load. Model files are large and should stay out of Git. This repo ignores common voice-model locations; check `git status` before saving models elsewhere.

### 2.3 Run the repository's generator

From the repository root with the virtual environment activated:

```bash
python scripts/voice.py out/voice-demo/script.txt out/voice-demo am_michael
```

The third argument is an available Kokoro voice ID; the script defaults to `am_michael`. This checked-in script requests English (`en-us`). You can change speaking speed through the `SPEED` environment variable:

```bash
SPEED=0.95 python scripts/voice.py out/voice-demo/script.txt out/voice-demo am_michael
```

PowerShell equivalent:

```powershell
$env:SPEED = '0.95'
python scripts/voice.py out/voice-demo/script.txt out/voice-demo am_michael
Remove-Item Env:SPEED
```

The generator writes:

| File | Purpose |
|---|---|
| `voice.wav` | Kokoro narration at the generated sample rate. Listen to this file and approve/correct the read. |
| `v16.wav` | Temporary mono 16 kHz audio used for transcription. |
| `words.json` | Word-level timestamps (`word`, `start`, `end`, in seconds), generated by faster-whisper. |

The first transcription run may download the `small.en` faster-whisper model. Hand-check `words.json`: automated word times can split, omit, or mis-time words. Make sure the final voice still matches `script.txt`. The generator currently leaves `v16.wav` in the output directory; it is an intermediate, not the final voice track.

## 3. Put the audio where the animation can load it

For a Remotion composition, browser-facing media must be inside `public/`. Copy the approved narration there:

```bash
mkdir -p public/voice-demo
cp out/voice-demo/voice.wav public/voice-demo/voice.wav
```

In a Remotion component, use `staticFile()` and Remotion's `<Audio>` component—do not read a local filesystem path in browser code:

```tsx
import React from 'react';
import { AbsoluteFill, Audio, staticFile } from 'remotion';

export const VoiceDemo: React.FC = () => (
  <AbsoluteFill>
    {/* The rest of the visual composition goes here. */}
    <Audio src={staticFile('voice-demo/voice.wav')} />
  </AbsoluteFill>
);
```

In the existing aging short, the audio pattern is already used in `src/videos/aging/Aging.tsx` with `staticFile("aging/mix.wav")`. Keep the filename in `public/` synchronized with the generated file. If you make an external audio mix, ensure its duration matches the video before muxing.

## 4. Use the word timings for animation

Remotion runs at a fixed frame rate; this repo's vertical shorts generally use 30 fps. Convert seconds to frames with `seconds * fps`, and use `useCurrentFrame()` so the scene can render deterministically at any frame.

Example helper that gets the active narration word from the generated JSON:

```tsx
import React from 'react';
import { useCurrentFrame, useVideoConfig } from 'remotion';

type Word = { word: string; start: number; end: number };

export const useActiveWord = (words: Word[]) => {
  const frame = useCurrentFrame();
  const { fps } = useVideoConfig();
  const seconds = frame / fps;
  return words.find((item) => seconds >= item.start && seconds < item.end)?.word ?? '';
};
```

Import `words.json` in a TypeScript project only after checking the repository's `tsconfig.json` and JSON import conventions. Word timings can drive an emphasis animation, prop entrance, or (if requested) captions. Do not put captions on screen when the selected style's rules say no captions. A more robust workflow is to hand-select the important words or phrases and put their animation times into the story's shared beat table rather than triggering a large visual event for every spoken word.

## 5. Remotion + Three.js / React Three Fiber

This is the main repository's 3D route. Remotion owns time and output frames; React Three Fiber draws the Three.js scene. `src/videos/bridge/Bridge.tsx` is the real production example and demonstrates the loading, layered shots, post-processing, and camera/world setup.

### 5.1 Understand the composition entry points

- `src/index.ts` registers `src/Root.tsx` for the 3D Remotion project.
- `src/Root.tsx` registers compositions and their frame counts/dimensions.
- `src/videos/bridge/Bridge.tsx` and `src/videos/aging/Aging.tsx` contain compositions.
- `2d/src/index.ts` and `2d/src/Root.tsx` are a separate 2D Remotion project.

Open the 3D Remotion Studio:

```bash
npm run studio
```

Open the 2D Remotion Studio:

```bash
npm run studio:2d
```

### 5.2 Minimal frame-driven Three.js scene pattern

The important rule is that a requested frame determines the entire visible state. Do not advance objects by `position.x += ...` on every render; compute their position from `useCurrentFrame()` instead. The existing production code uses more advanced scene/world modules, but this small component demonstrates the clock relationship:

```tsx
import React, { useRef } from 'react';
import * as THREE from 'three';
import { AbsoluteFill, useCurrentFrame } from 'remotion';
import { ThreeCanvas } from '@remotion/three';
import { useFrame } from '@react-three/fiber';

const Scene: React.FC = () => {
  const frame = useCurrentFrame();
  const hero = useRef<THREE.Mesh>(null);

  useFrame(() => {
    const seconds = frame / 30;
    if (!hero.current) return;
    hero.current.position.x = Math.sin(seconds * 0.8) * 1.4;
    hero.current.position.y = 1.1 + Math.sin(seconds * 2.2) * 0.12;
    hero.current.rotation.y = seconds * 0.45;
  });

  return (
    <>
      <color attach="background" args={['#86b8df']} />
      <ambientLight intensity={0.9} />
      <directionalLight position={[5, 8, 4]} intensity={2} castShadow />
      <mesh rotation={[-Math.PI / 2, 0, 0]} position={[0, 0, 0]} receiveShadow>
        <planeGeometry args={[40, 40]} />
        <meshStandardMaterial color="#72945e" roughness={0.95} />
      </mesh>
      <mesh ref={hero} position={[0, 1.1, 0]} castShadow>
        <dodecahedronGeometry args={[0.75, 0]} />
        <meshStandardMaterial color="#e9a54e" roughness={0.72} flatShading />
      </mesh>
    </>
  );
};

export const DemoScene: React.FC = () => (
  <AbsoluteFill>
    <ThreeCanvas width={1080} height={1920} shadows camera={{ fov: 38, near: 0.1, far: 100, position: [0, 3, 9] }}>
      <Scene />
    </ThreeCanvas>
  </AbsoluteFill>
);
```

For the actual cartoon style, do not stop at the dodecahedron: follow `SKILL.md` and the bridge source's authored characters, world, camera, ink, depth-of-field, grade, and sound pipeline. For an actual story composition, register its component and frame count in `src/Root.tsx`, following the existing `BridgeShort`/`AgingShort` pattern. Keep compositions at the requested dimensions and fps.

### 5.3 Preview and render a Remotion composition

Preview using Studio, then render a specific registered composition. Existing examples:

```bash
npm run render
npx remotion render src/index.ts AgingShort out/aging.mp4 --codec h264 --crf 16
npx remotion render 2d/src/index.ts MonoShort out/mono.mp4 --codec h264 --crf 16
```

`npm run render` renders `BridgeShort` to `out/bridge.mp4` as defined in `package.json`. Change the composition ID only to one that is actually registered. Use `out/` for generated renders; it is ignored by Git. Full 3D rendering can be slow and GPU/driver dependent. Read `CLAUDE.md` and `SKILL.md` before trying the high-resolution bridge render; do not assume a cloud CPU can render it quickly.

## 6. Standalone Three.js Stage Kit (not Remotion)

The paper pop-up and low-poly projects use the classic-script kits `ucimesehrou/src/stage.js` and `ucimesehrou/src/sound.js`. Their player template loads Three.js 0.187.0 as a module, assigns `window.THREE`, injects the kits and style, then calls:

```js
const S = await K.run(canvas, style, { samples: 3 });
window.seek = (t) => S.seek(t);
```

A style registers with `registerStyle({ id, duration, render, build(S), sound(k) })`. `build(S)` creates the world once and returns `update(t)`, which must set the full scene state from absolute time. `sound(k)` schedules sounds in seconds on the same clock. Use `K.rng(seed)` instead of `Math.random()` so every render is repeatable.

### Paper pop-up

Start from the actual fold-engine and style in `ucimesehrou/src/style.js`. Edit the palette, spread words, printed floor, and connected die-cut `parts`; preserve the page hinge, V-fold/box-fold/float-piece mechanics and their closed-book-fit check. Build the self-contained HTML player:

```bash
cd ucimesehrou
npm install
node build.cjs
python3 -m http.server 8000
```

Open `http://localhost:8000/` in a browser. Stop the server with Ctrl+C. To render an MP4, open another shell in `ucimesehrou/` and run:

```bash
node render.cjs 32
```

The first argument is the number of accumulation samples per frame. The render requires Chrome/Chromium, installed npm packages, and `ffmpeg-static` (installed by the package); high sample counts take much longer. See `ucimesehrou/README.md` for full-quality settings and output location.

### Low-poly miniature journey

Start from `ucimesehrou/low-poly/src/style.js`. Preserve its original camera path, stage/sound API, and content-driven timing object while replacing its own story objects, palette, and events. Build and preview from the subdirectory:

```bash
cd ucimesehrou/low-poly
node build.cjs
python3 -m http.server 8000
```

Open `http://localhost:8000/`; stop the server with Ctrl+C. For MP4, use another shell in that same directory:

```bash
node render.cjs 32
```

The low-poly build reads the shared Stage and Sound kits from `../src/`; do not create a divergent duplicate. See `ucimesehrou/low-poly/README.md` for render quality, GPU, and output details.

## 7. Verify the finished output

After render, verify the file exists and inspect its metadata:

```bash
ffprobe -v error -show_entries format=duration:stream=codec_name,width,height,r_frame_rate,sample_rate,channels -of default=noprint_wrappers=1 out/aging.mp4
```

For the Remotion 3D story workflow, run the repository QA utility when the expected audio/video exists:

```bash
python scripts/short_qa.py out/aging.mp4 out/aging/qa
```

Review the generated `report.md` and contact sheets, then watch/listen to the MP4. Check the opening, key transitions, final frame, narration timing, sound level, visual cropping, and any blank/frozen/pop frames. Fix and rerender if needed. A successful render command alone does not prove the result looks or sounds right.

## Common problems

- **Model file not found:** `scripts/voice.py` expects the ONNX and voice files in the output folder passed as argument 2. The separate `2d/voice_short.py` expects them in `2d/voice/` instead.
- **`ffmpeg` not found:** install it and ensure the command is on `PATH`; the root voice generator calls the system `ffmpeg` executable.
- **First run is slow:** model loading/download and faster-whisper's first model setup can take time. Let it complete before rerunning.
- **Pronunciation or timing is wrong:** edit `script.txt`, regenerate, listen to `voice.wav`, and correct `words.json` before timing animation.
- **Audio path fails in Remotion:** place the file under `public/` and reference it with `staticFile('relative/path.wav')`.
- **Blank Three.js render:** consult `CLAUDE.md` for software-GL `GL=swangle` settings and the `post.kick` workaround; these are environment-specific and can be slow.
- **Output looks different at another resolution:** scale pixel-based effects and check the output width/height. Follow `SKILL.md` for the 3D cartoon post-processing rules.
- **Model assets are huge or unlicensed:** don't commit model weights, generated binaries, or unapproved assets; inspect `git status` and project licenses before delivery.
